## Corrections incorporated into the suite

1. **“Always upgrade/deploy PHP first” is not universal.** Early Laravel/lock/dev-tool constraints may not support the proposed PHP. Find a tested overlap or use separate runtime trees and an explicit combined transition. Historical unsupported PHP is an isolated checkpoint, not a secure production destination.
2. **5.x minors can break compatibility.** Cover 5.0→5.1→…→5.8 before 6→…→13. Legacy shortcuts must not skip seven/eight upgrade guides.
3. **Laravel 9's exact floor is 8.0.2**, not arbitrary 8.0. Framework minimum, Composer constraint and documented PHP support range are distinct. Laravel 12's edition support includes 8.5; the archive's fixed table is not timeless.
4. **Laravel 13 is not just a PHP bump.** Official guide covers request-forgery changes, cache deserialization policy, prefix/cookie defaults, upsert/joined-delete SQL, domain precedence, contracts, queue events, model restoration and more. The suite retains the full guide and a mandatory applicability ledger.
5. **CSRF parity must be policy-aware.** Missing-token same-origin requests can legitimately pass Laravel 13's origin-aware default; tests that insist every such request returns419 are not universally correct. The archive's token-only middleware override is not adopted blindly. Preserve cross-origin defense and test actual middleware outside unit-test bypass.
6. **Cache deserialization needs exact config evidence.** Official13 guide documents new application config `serializable_classes=false`; legacy effective fallback can differ. Do not turn “null/unrestricted worked elsewhere” into a safe universal setting. Use supported explicit allow-lists/non-object payloads and test actual cache stores.
7. **Security fixes may intentionally change behavior.** Do not re-enable cookie serialization, accept unsafe SVG, unrestricted remote PDF fetching or weak CSRF just to match old output. Old vulnerable behavior is not an acceptance target.
8. **Laravel 11 slim-skeleton migration is not recommended for an existing 10 app** by official guidance. Keep Kernels/Handler/providers and sync only applicable changes. Do not regenerate auth or migrate every model to attributes.
9. **New-skeleton defaults are not all framework-wide changes.** Existing routing namespaces, explicit local-disk roots, session serialization and config prefixes can remain different. Inspect effective state rather than copying a fresh install.
10. **UUID/helper changes must exist on the runtime where applied.** Do not add a target-only trait/API into source code that must still deploy on the older framework. Check deployment order and the same-lock dual-runtime contract.
11. **Composer dry-run/Artisan/test commands are not automatically safe.** Composer plugins/scripts can run; Artisan/migrations/accessors/providers can perform IO. `migrate --pretend` is not a sandbox. The archive's route-key scanner boots Laravel despite its static source-expression scan; it is not used for our read-only audit.
12. **No blanket cache clears, installs or commits.** `optimize:clear` may clear application state. The Rector skill's `cache:clear`, global formatting, package installs, `git add -A` and commits are not adopted. Preserve user changes and approval boundaries.
13. **Do not infer an app version from a broad composer.json constraint.** Read the lock or explicitly trusted installed metadata; missing/drifting locks remain blockers. Branch-lock confidence is not production parity.
14. **Known-package observations are conditional.** Dompdf/backup/notification workarounds from one app are investigation leads, not universal fixes. Scope optional package/DB/front-end majors separately; do not pin internal package versions without a demonstrated reason.
15. **MySQL8 authentication claims need minor-line precision.**8.0, 8.4 and 9 differ; `mysql_native_password` is not simply disabled across all “8.x.” Framework compatibility does not establish DB vendor security support.
16. **The v13.38.0 cumulative input-key limit is verified in source, undocumented.** The earlier “unverified” conclusion was incorrect: guide/changelog silence was not evidence of absence. The [pinned TransformsRequest snapshot](official/13.x/TransformsRequest-v13.38.0.php) has `$maxKeyBytes = 20 * 1024 * 1024` and throws `PostTooLargeException` / HTTP 413 above that total, counting nested key prefixes and byte lengths. It applies through the default global TrimStrings/ConvertEmptyStringsToNull flow; add a relevant large form/JSON/key-count gate. The introduction commit is `1b8b12d307`; post-tag `31dbc2b9b0` is Unreleased, so check the next actual patch source instead of projecting branch behavior onto the tag.
17. **Shared test syntax is version-dependent.** The archive's PHP 7.4/PHPUnit 7→12 techniques do not automatically work on PHP 5.4/PHPUnit 4/5; even `void` is too new for early baselines. Use compatible harness adapters and compare the same behavioral cases.

## What is intentionally not bundled

The four downloaded PHP probes are **not installed or run**. **`compare-junit.php` does not boot the app**; it reads two XML reports. The route-matrix, route-key and error-page probes do bootstrap Laravel, and some write artifacts, so those need app-specific fixtures, runtime compatibility and side-effect isolation. No source from the ZIP is copied because its license was not supplied. The new [compare_junit.py](../scripts/compare_junit.py) is independently written with Python stdlib, compares `classname::name` identities/statuses, reports assertion differences as INFO and never boots the app. Its fixtures, inventory fixtures and source/link checks live in `check.py`. Runtime probes still belong only to an authorized app/hop.
